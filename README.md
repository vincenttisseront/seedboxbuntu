# SeedBoxBuntu

ISO Ubuntu Server 24.04 qui installe seule une seedbox Docker sécurisée : Traefik + Authelia, Servarr (Radarr, Sonarr, Prowlarr…), Jellyfin, Seerr, qBittorrent (direct ou VPN), autobrr, cross-seed, qbit_manage, Homepage, Dockge, Watchtower, agrégateur de releases intégré, console web, menu texte, partages et catalogue d'applications.

Ce dossier contient **tout** ce qu'il faut pour reconstruire l'ISO. Il remplace l'ancien script unique `build-seedboxbuntu.sh`, où l'appliance entière était embarquée en here-documents.

## Construire l'ISO

| Système | Commande | Prérequis |
|---|---|---|
| Windows 10/11 | `powershell -ExecutionPolicy Bypass -File .\build.ps1` | Docker Desktop démarré (conteneurs Linux), ~20 Go libres |
| Linux / WSL2 | `./build.sh` | `xorriso curl python3 zstd git openssl` (installés via apt si absents)  |

L'ISO est écrite dans `out/` (Windows) ou dans le dossier courant (Linux). `./build.sh --help` liste les variables (`HOST_NAME`, `KEYBOARD`, `TIMEZONE`, `EXTRA_CA_CERTS`…), `build.ps1` expose les mêmes réglages en paramètres.

## Modifier l'appliance

- **Modifier un fichier** : éditez-le dans `rootfs/`, `stack/` ou `templates/` ; il est copié à son emplacement au prochain `build.sh`. Rien à régénérer, rien à recoller dans un script.
- **Ajouter un fichier** : déposez-le au bon endroit de l'arborescence. Le chemin dans `rootfs/` est son chemin sur le serveur (`rootfs/etc/foo.conf` → `/etc/foo.conf`) ; `stack/` et `templates/` vont sous `/usr/share/seedboxbuntu/`.
- **Droits** (fonction `appliance_mode` de `lib/40-appliance.sh`, indépendante du bit exécutable pour résister à une copie Windows ou un zip) : `etc/sudoers.d/*` en 0440 ; `usr/local/sbin`, `usr/local/bin`, `etc/update-motd.d`, `seedboxctl.py`, `server.py`, `postinstall.sh` en 0755 ; le reste en 0644.
- **Modifier la construction elle-même** (GRUB, autoinstall, late.sh…) : le module correspondant de `lib/`. Les fichiers `late.sh` et `update.sh` sont des here-documents de `50-late.sh` et `55-update.sh`.
- **Fins de ligne** : tout doit rester en LF. `.gitattributes` s'en charge avec git ; `build.sh` refuse un fichier en CRLF et le dit.

## Mettre à jour un serveur déjà installé, sans ISO

Une fois les sources poussées sur GitHub (`vincenttisseront/seedboxbuntu`, dépôt privé par défaut), le serveur se met à jour seul depuis la console web : **Paramètres > Mise à jour de l'appliance** (ou `seedboxctl appliance ...`, ou l'entrée « Mise à jour de l'appliance » du menu texte).

1. « Rechercher une mise à jour » compare le commit installé à celui de la branche suivie (`main`) et liste les nouveautés. Le contrôle se refait seul toutes les 6 h ; une bannière s'affiche sur la page Applications quand une version est disponible.
2. « Mettre à jour » télécharge l'archive du commit, la **vérifie** (Python, shell, JSON, fichiers indispensables, sudoers, démarrage de la nouvelle version, docker-compose.yml), sauvegarde les fichiers remplacés, installe `rootfs/`, `stack/` et `templates/` avec les mêmes droits que l'ISO, active les services, puis applique la stack (`seedboxctl upgrade`). Rien n'est installé si une vérification échoue. Pas de redémarrage du serveur : seule la console redémarre à la fin, et la page se recharge.
3. « Annuler la dernière mise à jour » remet les fichiers, la version et l'état d'avant (trois sauvegardes conservées). Les données et les migrations déjà faites dans les applications ne sont pas annulées.
4. Si l'étape finale (téléchargement d'images, liaisons) échoue, les fichiers restent installés et `seedbox-upgrade.service` réessaie toutes les 2 minutes.

Dépôt privé : enregistrez un jeton GitHub en lecture seule dans « Source des mises à jour », ou dans le menu texte. Le jeton n'est envoyé qu'à `api.github.com`. Dépôt, branche ou étiquette se changent dans « Source des mises à jour ».

### Canaux, planification, garde-fou et signature

Dans **Paramètres > Mise à jour de l'appliance > Canal, contrôles et planification** :

- **Canal** : *stable* suit la dernière version publiée sur GitHub (étiquette `v…`, avec ses notes) ; *développement* suit le dernier commit de la branche.
- **Mise à jour automatique** : jours et heure au choix (`seedbox-appliance.timer`). Une version écartée par le garde-fou n'est pas réessayée seule.
- **Garde-fou** : après l'installation, l'état des services est surveillé quelques minutes ; si l'un d'eux qui fonctionnait avant tombe, la version précédente est rétablie automatiquement, la version fautive est marquée « écartée » et une alerte critique part. « Réessayer quand même » force une nouvelle tentative.
- **Versions signées** : une version publiée porte `manifest.json` (empreinte SHA-256 de chaque fichier, commit, étiquette) et `manifest.json.sig` (signature SSH, espace de noms `seedboxbuntu-release`). Enregistrez la clé publique de confiance dans la console ; avec « N'installer que des versions signées », seule une signature valide (ou un commit vérifié par GitHub) est acceptée. Un manifeste altéré ou qui ne correspond pas aux fichiers est toujours refusé.

Publier une version :

```
git tag v1.5.0 && git push origin v1.5.0       # .github/workflows/release.yml teste, construit le manifeste et publie
```

Pour signer, créez une clé dédiée (`ssh-keygen -t ed25519 -f release_key -C seedboxbuntu`), placez la clé privée dans le secret GitHub `RELEASE_SIGNING_KEY` et collez `release_key.pub` dans la console. Manuellement : `tools/manifest.py build --tag v1.5.0 --commit <sha>`, `sign`, `verify`.

La version installée devient « AAAA.MM.JJ-HHMM » de la date du commit (UTC). Une ISO plus récente remplace sans difficulté une mise à jour faite depuis la console ; une ISO plus ancienne est refusée comme d'habitude. L'ISO note le commit de ses sources (`SOURCE_COMMIT`) quand `build.sh` est lancé depuis un clone git, ou avec `SB_SOURCE_COMMIT="<sha> <date ISO>"`.

Points d'attention :

- **Invitations** : la page `/invite/<jeton>` est la seule route publique (sans connexion unique). Elle est limitée en débit par Traefik, par adresse dans la console, et ne donne jamais accès à l'administration ; seule l'empreinte du jeton est conservée.
- **Journal d'audit** : aucun mot de passe, clé ni jeton n'y est écrit ; les empreintes chaînées font apparaître une modification maladroite, mais ne protègent pas d'un administrateur qui sait les refaire : exportez-le régulièrement.
- **Rôle observateur** : un compte du groupe `observers` (créé avec `seedboxctl user add <nom> --role observer`, ou depuis Comptes) ne fait que regarder : vue d’ensemble, page maison, applications, système, alertes et rapport. La restriction est appliquée par le serveur (liste blanche de routes en lecture, seule exception : ses propres préférences d'affichage), pas seulement par l'interface ; les alertes et l'état de l'appliance lui sont filtrés (ni secrets, ni adresses, ni configuration). Dans Seerr il reçoit le droit « demander » seulement.
- **Rapport hebdomadaire** : désactivé par défaut. `seedbox-report.timer` passe chaque jour à 08:10 mais n'envoie que le jour choisi, une seule fois, par les canaux d'alerte configurés. Le texte envoyé est en français ; la console l'affiche aussi sans l'envoyer.
- **Ressources par conteneur** : relevées toutes les 5 minutes avec les mesures de la machine (clés `ctr.*` de `metrics.db`, masquées de l'historique machine). Trois dérives alertent : mémoire à plus de 90 % de la limite 3 mesures de suite, fuite probable (plus de 512 Mo et plus de 2 fois la médiane habituelle), processeur à plus de 90 % de la machine pendant 30 minutes (Jellyfin ignoré : transcodage). Seuils modifiables dans Système.
- **Vérification d'une sauvegarde** : répétition à blanc dans un dossier temporaire, sans démarrer de conteneur : elle prouve que l'archive se déchiffre, que les bases SQLite sont saines et que les réglages se lisent, pas que les applications redémarreront. Le test de restauration hors serveur (mensuel) reste le contrôle de bout en bout de la copie distante.
- **Fenêtre de maintenance** : jours et heures (la fin peut passer minuit). Une tâche automatique qui se déclenche hors fenêtre est mise en attente et lancée par le passage de surveillance de 5 minutes dès l'ouverture ; un lancement manuel n'est jamais retenu, ni les sauvegardes et la surveillance.
- **Activité par personne** : désactivée par défaut. Elle lit Jellyfin et Seerr, montre « en lecture » sans jamais le titre regardé, et repère les comptes inactifs depuis 30 jours.
- **Vulnérabilités** : Trivy est lancé dans un conteneur éphémère (`aquasec/trivy`, la base est mise en cache dans un volume) ; seules les failles critiques et élevées qui ont un correctif sont comptées. Désactivé par défaut ; l'analyse hebdomadaire (`seedbox-vulnscan.timer`, dimanche matin) respecte la fenêtre de maintenance et demande l'accès à Internet.
- **Mode vacances** : met en pause les torrents actifs (ceux qui l'étaient déjà ne sont pas touchés), fait démarrer les nouveaux en pause et refuse les liens d'invitation ; limité à 120 jours. À la date, ou à « Désactiver », seuls les torrents mis en pause par le mode reprennent et la préférence de qBittorrent est rétablie ; si qBittorrent est injoignable à ce moment, le mode reste actif et la reprise est retentée toutes les 5 minutes.
- **Santé des disques** : `smartctl -n standby` (un disque en veille n'est jamais réveillé) une fois par heure ; clés `smart.*` de `metrics.db`. L'alerte part de la tendance (secteurs réalloués en hausse sur 30 jours, secteurs en attente, usure NVMe, température), pas d'une seule lecture. Une machine virtuelle, un RAID matériel ou certains ponts USB ne laissent pas voir les disques : la page le dit et reste vide.
- **Débit par plages** : la limite est posée dans qBittorrent (débits globaux), elle ne touche ni Jellyfin ni les autres applications ni le réseau de la maison. Un réglage fait à la main dans qBittorrent est conservé jusqu'au prochain changement de plage ; en désactivant les plages, les limites d'origine sont rétablies.
- **Objectifs de ratio** : le ratio vient des statistiques de qBittorrent, pas du tracker : après un import ou un nettoyage il peut différer, et celui du tracker fait foi. Aucune alerte tant que moins de 5 Go ont été reçus (réglable).
- **Mise à jour par lots** : exclut `traefik`, `authelia` et `gluetun` (une coupure efface la session de la console ou le tunnel de qBittorrent) et les services épinglés. Le test vaut ce que vaut le contrôle d'état de l'image : sans lui, le service est seulement vu « en marche ». Au premier échec, le lot s'arrête (sauf « Continuer »).
- **Comparaison de sauvegardes** : les fichiers de réglages sont comparés ligne par ligne ; les mots de passe, clés et jetons sont remplacés par un repère (`[masqué:xxxx]`) qui change si la valeur change. Les bases de données sont seulement signalées « modifiées ». Il faut la clé de chiffrement des sauvegardes ; rien n'est restauré.
- **Dépannage guidé** : lit l'état du conteneur, les redémarrages, le contrôle d'état, la mémoire, l'espace disque, les dépendances et le journal ; propose redémarrer, revenir à la version précédente ou nettoyer, mais chaque action reste un clic confirmé.
- **Accès de secours** : le code est affiché une seule fois (seule son empreinte est gardée dans `/etc/seedboxbuntu/emergency.json`, incluse dans les sauvegardes). Il ne s'utilise qu'en local (console de la machine ou SSH), une seule fois : un mot de passe temporaire est créé, les secondes étapes sont retirées (sauf `--keep-2fa`) et le code est remplacé. Cinq essais faux verrouillent l'accès quinze minutes ; chaque essai est dans le journal d'audit et déclenche une alerte. Rangez le code imprimé sous clé : qui le détient et accède au serveur reprend la main.
- **Liste des médias** : titres, identifiants, suivi, qualité et dossier uniquement, pas les fichiers vidéo. Le réimport n'ajoute que les titres absents, sans lancer de recherche, et se simule d'abord ; il a été écrit d'après l'API documentée de Radarr et Sonarr mais pas essayé contre une vraie bibliothèque : simulez, puis importez un petit essai.
- **Mon espace (`/me/`)** : seconde route servie après Authelia pour tous les comptes, sur son propre secret (`X-Seedbox-Me-Secret`) que la console n'accepte que pour `/me/` : les en-têtes d'administration sont effacés par Traefik et refusés s'ils arrivent quand même. L'identité vient uniquement de `Remote-User` ; la page est en lecture seule, limitée à 60 lectures par minute et par compte, et n'expose aucun identifiant interne.
- **Télécommande** : la page `#telecommande` garde la connexion et la double authentification de la console. « Tout reprendre » ne relance que les torrents que la télécommande a mis en pause, et la pause est refusée pendant le mode vacances. Hors de la maison, il faut un domaine ou Tailscale ; l'installation comme application dépend du navigateur.
- **Journal des réglages** : suit les fichiers `*.json` de `/etc/seedboxbuntu` (pas les comptes, le `.env` ni les bases ; le code de secours est exclu). Les copies (20 par fichier) sont dans `/var/lib/seedboxbuntu/changelog/`, en 0600 : elles contiennent les réglages tels quels, secrets compris, alors que l'écran les masque. L'auteur est une déduction (même minute dans le journal d'audit), pas une preuve ; « Revenir » ne vaut que pour l'entrée la plus récente d'un fichier.
- **Simulation de restauration** : démarre l'image déjà présente de Radarr, Sonarr, Prowlarr ou Lidarr avec la configuration de la sauvegarde, sans réseau, avec 768 Mo et un processeur au plus, puis teste l'API avec la clé sauvegardée. Elle exige environ 1,5 Go de mémoire libre et prouve que la sauvegarde se relit, pas que les médias ou les bases de Jellyfin sont complets. Le démarrage de ces images (variables `PUID`/`PGID`, `curl` dans l'image) a été écrit d'après leur fonctionnement habituel et n'a été essayé ici qu'avec un faux Docker : vérifiez-le une fois sur votre serveur.
- **Espace par dossier** : `du` en priorité basse (`nice`, `ionice`), une fois par jour, en tâche de fond ; clés `du.*` de `metrics.db`, masquées de l'historique machine. La mesure reste dans un seul disque et ignore les liens : c'est une bonne approximation. L'alerte n'apparaît que si la prévision de saturation d'un disque est déjà fiable et qu'un dossier grossit d'au moins 50 Mo par jour.
- **Rotation des secrets** : seulement les clés d'API de Radarr, Sonarr et Prowlarr et le secret console ↔ Traefik. Pas les secrets d'Authelia (la clé de stockage chiffre sa base), les mots de passe des comptes, la clé de chiffrement des sauvegardes ni le mot de passe de qBittorrent. L'application concernée est indisponible quelques dizaines de secondes ; si elle ne répond pas avec la nouvelle clé, l'ancienne est remise. L'ancienne valeur n'est jamais écrite dans un journal.
- **Qualité des médias** : lecture seule ; « manquants » dépend de la date de sortie connue de Radarr et Sonarr, la compression est une estimation (taille divisée par la durée annoncée), les doublons sont repérés par le nom. La seule action lance une recherche (20 titres au plus, 50 au maximum) : Radarr et Sonarr décident ensuite de télécharger ou non. Écrit d'après l'API documentée de Radarr et Sonarr (v3), essayé ici avec de fausses réponses seulement.
- **Contrôle des liens** : utilise les fonctions de test des applications (`/testall`, `/test`) ; les indexeurs ne sont pas contactés. Un test réussi prouve que l'adresse et la clé sont bonnes, pas qu'une recherche donnera des résultats.
- **Bilan mensuel** : désactivé par défaut, car il rend visible à l'administrateur l'usage de chacun : à annoncer aux personnes. Que des nombres (demandes sur 30 jours, disponibles, en attente), jamais un titre. Chacun voit son propre bilan sur « Mon espace » dans tous les cas ; les lectures dans Jellyfin ne sont pas comptées.
- **Partage d'un titre** : crée des liens durs des fichiers du titre dans `<stockage>/media/partages/<id>/` (aucune copie, mais le titre doit être sur le même disque : sinon le partage est refusé), une médiathèque Jellyfin « Partage <id> » et une invitation à usage unique dont le compte ne voit que cette médiathèque, ne télécharge pas et n'a aucun droit de demande Seerr. À l'échéance (durée + 1 jour), la médiathèque, le dossier de liens et l'invitation sont supprimés ; les fichiers d'origine ne sont jamais touchés. La personne voit les noms de fichiers. Les appels à Jellyfin (médiathèques virtuelles, dossiers autorisés par compte) suivent son API documentée mais n'ont été essayés qu'avec un faux Jellyfin : faites un premier partage d'essai.
- **Surveillance du VPN** : désactivée par défaut (elle interroge `api.ipify.org` depuis le serveur, qui voit alors l'adresse de la maison). Compare l'adresse de sortie vue par gluetun à celle du serveur toutes les 5 minutes ; l'arrêt automatique ne met en pause que si les deux sont identiques, et ne reprend que les torrents qu'il a lui-même mis en pause. gluetun coupe déjà le trafic hors tunnel et qBittorrent partage son réseau : une vraie fuite est improbable, c'est un filet de sécurité.
- **Bibliothèques, remplacements, allègement** : tout part d'un relevé de Radarr et Sonarr (nuit, ou à la demande) ; écrit d'après leur API documentée (v3) et essayé ici avec de fausses réponses seulement, jamais contre de vrais Radarr, Sonarr ou Jellyfin. Les copies cachées ne sont reliées qu'après comparaison complète octet par octet, sur le même disque, et le fichier de la médiathèque n'est jamais touché. Un remplacement exige la corbeille de Radarr et Sonarr, respecte un budget de croissance par volume et ne lance qu'un téléchargement : c'est Radarr ou Sonarr qui décident ensuite d'importer (une version choisie à la main qui n'est pas une « amélioration » pour eux peut être refusée à l'import ; non vérifié). La recompression x265 prend plusieurs heures par film, tourne dans la fenêtre nocturne, vérifie la durée et les pistes vidéo de la sortie et garde l'original dans `.sb-corbeille/` pendant le délai choisi ; un fichier encore lié à un torrent n'est pas proposé, car il ne libérerait rien. Les déplacements entre deux disques sont des copies suivies d'une suppression : longs.
- **Optimisation des seeds** : l'historique est un relevé par heure ; les chiffres sur 7 et 30 jours sont partiels pendant les premiers jours. Sans règle déclarée pour un tracker (ratio, durée), rien n'est jamais proposé au retrait : la console ne devine pas. Retirer un torrent n'économise presque jamais d'espace (ses fichiers ont un autre lien, la médiathèque) ; l'intérêt est d'arrêter de partager ce qui n'apporte rien. La suppression des fichiers n'est permise que si chaque fichier a un autre lien.
- **Connecteur Ollama** : désactivé par défaut. Seuls des agrégats partent (jamais le nom d'un torrent ni d'une personne) ; les trackers sont renommés « tracker A », « tracker B » tant que l'option des vrais noms est décochée, et quelques titres de films ne partent que si elle est cochée. Les adresses locales de lien, multicast et métadonnées sont refusées, le certificat HTTPS est vérifié par défaut, le jeton éventuel (proxy) est stocké en 0600 et jamais renvoyé. Un serveur en http expose le résumé sur votre réseau local. Le modèle ne commande rien ; son avis est indicatif et peut être faux.
- **Agrégateur** : cette première version couvre le cœur (catalogue, doublons, filtres, collecte planifiée, envoi à qBittorrent, purge, santé des sources). Elle n'a été éprouvée qu'avec des réponses simulées, pas encore avec de vrais Prowlarr, Jackett ou trackers. Les trackers privés sans flux Torznab (ratio, messages non lus, sessions protégées comme C411) et le client Deluge ne sont pas repris, et P2P Aggregator et tracker-session sont retirés : ratios réels des trackers, messages non lus et sessions protégées ne sont plus disponibles tant que des lecteurs de trackers natifs ne sont pas écrits. La mise à jour supprime leurs conteneurs, images et sources mais garde leurs données dans `config/p2p-aggregator` (base et comptes de trackers) ; l'optimisation des seeds se rabat sur le ratio mesuré par qBittorrent. Le rapprochement des titres est approché : un titre court ou ambigu peut rester séparé ou, rarement, être fusionné à tort ; la distance d'édition ne joue qu'à partir de 8 caractères pour que « Alien » et « Aliens » restent distincts.
- **Espace disque** : la mesure s'appuie sur `du` (quelques minutes sur un gros disque, lancée à la demande ou quand elle a plus de 6 h) et sur `docker system df` ; elle n'a été éprouvée qu'avec de fausses sorties, pas encore sur un vrai serveur plein. Les propositions « Libérer » (corbeille, Docker, journal, apt) agissent après confirmation ; les autres (orphelins, partage, seeds, agrandissement) ne font qu'ouvrir la bonne page, rien n'est supprimé à votre place. L'estimation des seeds (30 % des téléchargements) est indicative. Agrandir un disque virtuel reste une opération de votre hyperviseur.
- **Agrégateur, liens vers les trackers** : la page d'un torrent n'apparaît qu'après la prochaine collecte (les lignes déjà en base n'ont pas encore l'adresse) ; seules les adresses de détail sont gardées, jamais les liens de téléchargement ni les clés.
- **Sous-domaines** : ils s'ajoutent aux chemins, ils ne les remplacent pas. Chaque nom doit exister dans votre DNS (un CNAME vers l'adresse principale suffit). Avec l'autorité locale, installez-la sur vos appareils ; avec Let's Encrypt, le défi DNS donne un seul certificat générique, le défi HTTP exige que chaque nom soit public et le port 80 ouvert. Si aucune adresse de l'appliance n'est sous le domaine choisi, la page de connexion devient `auth.<domaine>` (à créer aussi). Les adresses que les applications s'échangent entre elles (Seerr vers Radarr...) restent celles par chemin. Tableau de bord, console, Authelia et Traefik ne sont pas proposés en sous-domaine. Éprouvé avec des fichiers générés et lus (YAML, règles Authelia, certificat), pas encore avec un vrai navigateur derrière votre DNS.
- **Entretien des médias** : « jamais lu » repose sur les lectures que Jellyfin garde ; s'il n'en remonte aucune, la liste reste vide plutôt que fausse. Le contrôle d'intégrité ne voit pas un défaut au milieu d'un fichier. Les sous-titres externes (.srt) ne sont pas comptés. Les watts et le prix du kWh sont des réglages : le coût par To est une estimation, et un partage réseau n'est pas mesurable. Les quotas des invités ne lèvent jamais une suspension faite à la main.
- **Réseau et SSH** : un changement d'adresse peut couper l'accès à la console. « Appliquer » programme donc un retour arrière (minuterie systemd, 120 s) et ne le désarme que si vous cliquez sur « Confirmer » depuis la nouvelle adresse (nouvelle connexion Authelia nécessaire) ; le certificat et les adresses des applications suivent la nouvelle IP. Seules les cartes en*, eth* et wl* sont proposées, en IPv4. Le contrôle « SSH durci » lit `sshd -T` (le dossier /run/sshd est créé au besoin, car Ubuntu 24.04 démarre SSH à la demande) et, à défaut, les fichiers de configuration ; il indique la raison au lieu d'afficher des « ? ».
- **Page maison** : `#maison` ouvre le mode kiosque sur une vue agrégée (services, alertes, téléchargements, VPN, dernière sauvegarde, espace) qui se met à jour toutes les 30 secondes. Aucun geste, aucune adresse IP affichée ; un compte observateur suffit, mais l'écran doit s'être connecté une fois (double authentification comprise).
- **Notifications push** : chaque appareil s'abonne depuis Alertes ; le serveur chiffre le message (RFC 8291) et le signe (VAPID, RFC 8292) puis l'envoie au service de push du navigateur (Google, Mozilla, Apple, Microsoft), qui ne voit que du texte chiffré. Seules ces adresses sont acceptées (pas d'envoi vers une adresse choisie par un utilisateur). Il faut HTTPS, un navigateur compatible et `python3-cryptography` ; sur iPhone, la console doit être ajoutée à l'écran d'accueil. Les observateurs peuvent s'abonner.
- **Réglages de la console** : le fichier exporté ne contient ni comptes, ni médias, ni applications ; sans l'option « secrets », les jetons, webhooks, mots de passe et le sujet ntfy sont masqués (à l'import, un secret masqué laisse la valeur actuelle). L'import commence par une simulation et n'applique que les sections cochées et valides.
- **Notifications** : la cloche réunit les alertes en cours et les derniers événements (200 conservés, sans détail sensible) ; « lu » se mesure par compte.
- **Import** : déposez les sauvegardes de l'ancienne seedbox dans `<stockage>/import`. Seule la base de données des applications est reprise (la clé d'API, le port et la connexion restent ceux de ce serveur), les chemins sont convertis d'après une table « ancien dossier → nouveau dossier », une sauvegarde complète est faite avant, et l'ancienne base est gardée. Les torrents sont ajoutés en pause.

### Confort d'usage (console)

- **Recherche rapide** : `Ctrl+K` (ou `⌘K`) ouvre une recherche de pages, d'applications et d'actions, entièrement au clavier.
- **Vue d'ensemble personnalisable** : « Personnaliser » déplace, masque ou affiche chaque tuile ; la disposition est mémorisée par compte sur le serveur, et le masquage se défait depuis la notification.
- **Mode kiosque** : `#kiosk` (bouton « Mode kiosque ») affiche la vue d'ensemble seule, en grand, avec l'heure, sur un écran mural ; elle se rafraîchit seule et garde l'écran allumé quand le navigateur le permet. Elle dépend de la session de connexion unique : si celle-ci expire, la page se recharge pour redemander la connexion.
- **Assistant de configuration** : page « Assistant » et tuile « Configuration » ; un rappel apparaît tant qu'un point de sécurité ou de données reste à régler (et peut être écarté).
- **Défaire** : les actions réversibles (masquer une tuile, mettre à la corbeille) proposent « Défaire » pendant quelques secondes dans la notification.
- **Langues** : français (d'origine) et anglais, choisis dans « Affichage » et mémorisés par compte. Le dictionnaire anglais (`console/web/lang-en.js`) est appliqué au texte affiché ; un texte absent reste en français, jamais une clé brute. Restent en français : les textes envoyés par ntfy, Discord et e-mail, les pages d'erreur Traefik, les journaux, et les contenus venant de tiers (notes de version GitHub, catalogue personnel).

## Charte graphique de la console

Toute l'interface (console, page d'invitation, pages d'erreur, connexion Authelia, Homepage) partage la même identité :

- **Jetons** : `console/web/tokens.css` est l'unique source des couleurs, espacements, rayons, tailles, ombres et seuils (`--th-warn: 85`, `--th-crit: 95`). `app.css` ne contient aucune couleur en dur ; la densité, le contraste élevé et la taille du texte ne font que redéfinir ces jetons.
- **Échelle d'états** : `ok`, `attention`, `erreur`, `information`, `inconnu`, toujours en icône + texte + couleur (pastilles, notices, notifications, tuiles, jauges).
- **Navigation** par groupes (Services, Stockage, Réseau, Sécurité, Exploitation) : barre latérale sur ordinateur, barre du bas et feuille de navigation sur téléphone.
- **Retour d'action** uniforme : notification pour une action courte, tiroir de tâche pour une opération longue, confirmation dans une boîte de dialogue pour tout ce qui détruit.
- **Affichage** (menu « Affichage ») : clair / sombre / automatique, densité, contraste élevé, taille du texte ; mémorisés dans le navigateur.
- **Pages** : « Vue d'ensemble » (mêmes tuiles que Homepage) et « Guide de style » (chaque composant avec les vrais styles, mesure de contraste AA en direct).
- **Vocabulaire** : `docs/GLOSSAIRE.md` fixe les libellés, les verbes d'action et les formats de dates, tailles et durées ; `ui.js` en est l'unique implémentation.
- **Hors console** : pages `/invite/…` et `/errors/50x` (Traefik, pour 502-504) sur les mêmes jetons ; logo et favicon Authelia (`templates/config/authelia/assets/`) ; `templates/config/homepage/custom.css`.

Ajouter une page : une section `view-…` dans `index.html`, son entrée dans `NAV` de `ui.js` (groupe, libellé, icône), un chargeur dans `app.js`. Les tests refusent une couleur en dur, un bouton hors des classes `btn`/`tab`/`seg`/`icon-btn`/`tabbar-item` et un libellé qui contredit le glossaire.
