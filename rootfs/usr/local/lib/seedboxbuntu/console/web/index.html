Contrôle de santé

Interroge l'API de chaque application et vérifie leurs liaisons : Radarr, Sonarr et Prowlarr entre eux, Jackett et FlareSolverr, clients qBittorrent, Seerr, Jellyfin, autobrr, Dockge.

    Configuration et mises à jour

    Chaque étape de liaison entre applications est suivie ici. Une étape annexe en échec (Jackett, applications ajoutées...) n'arrête pas l'appliance : elle est réessayée chaque heure.

    Catalogue d'applications
    
    
    Ajoutez des applications à la seedbox en un clic. Celles marquées « intégré » sont reliées aux autres (Prowlarr, qBittorrent, Jellyfin...) ; celles venues de linuxserver.io sont installées en mode générique, derrière la connexion unique et réservées aux administrateurs : elles ne fonctionnent que si l'application accepte d'être servie sous un sous-chemin.
    
    
    
    
    
      
    Packs
    
      
    Plusieurs applications reliées entre elles, installées d'un seul geste. Celles déjà présentes sont ignorées.
    
      
    
    
    
    
    
      
    Qualité vidéo (Recyclarr)
    
      
    Profils de qualité et formats personnalisés des guides TRaSH, appliqués à Radarr et Sonarr puis resynchronisés chaque jour. Ne change pas les films déjà téléchargés.

    Partages réseau et disques
    
    
    Un NAS (SMB ou NFS) ou un disque branché sur le serveur peut recevoir les téléchargements, les fichiers .torrent ou les bibliothèques. Les applications sont reconfigurées automatiquement.

    UsageEmplacementSous-dossierChemin dans les applications
    
        
      
    
      
    Changer l'emplacement des téléchargements ne déplace pas les torrents existants : ils continuent d'être partagés depuis leur emplacement actuel.
    
    
    
    
    
      
    Ajouter un partage
    
      
      
      
      
      
      
      
      
      
    Le compte doit pouvoir écrire dans le partage. Les fichiers appartiennent aux applications (utilisateur 1000) côté serveur.
    
      
    Autorisez l'adresse IP de ce serveur dans l'export, et mappez les accès en écriture (all_squash, anonuid=1000 ou équivalent du NAS).
    
      
    Seuls les disques non montés sont proposés. Le disque n'est pas formaté : son contenu est conservé.

    qBittorrent : accès direct ou VPN
    
    
    
    
    
      
    Passer par un tunnel VPN (WireGuard)
    
      
    Par défaut qBittorrent est utilisé en accès direct, sans VPN : le port de partage 6881 est ouvert sur le serveur. Renseignez un fournisseur pour faire passer tout son trafic par le tunnel.
    
      
      
      
      
      
      
    Proton VPN : générez la configuration WireGuard avec l'option NAT-PMP activée.
    
      
    
        
        
      
    
    
    
  
    

  
    
    
    Adresse et certificat
    
    
    
      
    Télécharger l'autorité locale
    
      
    À installer sur vos appareils pour éviter l'alerte du navigateur en mode auto-signé.
    
    
    
    
    
      
    Nom personnalisé
    
      
      
      
    Vide : l'adresse IP du serveur, suivie automatiquement. Un nom doit pointer vers ce serveur dans votre DNS (un seul enregistrement : les applications sont servies par chemin). L'adresse IP reste toujours utilisable. Avec Let's Encrypt, ouvrez aussi le port 80 depuis Internet.
    
      
    
    
    
    
      
    Adresses supplémentaires
    
      
      
    Chaque adresse reçoit son propre cookie de connexion et sa place dans le certificat de l'appliance. Une adresse non déclarée ici est redirigée vers l'adresse principale.
    
      
    
    
    
    
      
    Accès distant : Tailscale (expérimental)
    
      
    Publie l'appliance sur votre réseau privé Tailscale avec un vrai certificat HTTPS, sans ouvrir de port de la box. Prérequis : un compte Tailscale, « HTTPS Certificates » activé dans sa console d'administration. Générez une clé d'authentification (Settings, Keys) ou laissez le champ vide pour valider la connexion depuis un lien.
    
      
    
      
    
        
        
        
    
      
    
    
    
    
    
      
    Let's Encrypt par DNS (sans ouvrir le port 80)
    
      
    Pour un nom de domaine personnalisé : le certificat est obtenu en créant un enregistrement DNS chez votre fournisseur, donc sans exposer le serveur à Internet. Renseignez d'abord le nom et l'e-mail ci-dessus.

      Alertes
      
    
      L'appliance se surveille toutes les 5 minutes : services arrêtés, disque presque plein, mise à jour bloquée, étape de configuration en échec, certificat proche de l'expiration. Un problème n'est signalé qu'après deux constats successifs, rappelé selon l'intervalle choisi, et un message « rétabli » l'annonce à sa disparition.

        Sauvegardes
        
    
        Configuration de l'appliance : comptes, clés, réglages des applications, partages, applications ajoutées. Les médias et téléchargements n'en font pas partie (c'est le stockage), ni les caches, journaux et vignettes de Jellyfin. L'archive est chiffrée avec une clé propre à ce serveur. Restaurez après le premier déploiement d'un serveur neuf.

        Mise à jour de l'appliance
        
      
        Installe la dernière version de SeedBoxBuntu depuis GitHub, sans passer par l'ISO : fichiers de l'appliance, modèles et stack. Comptes, secrets, bibliothèques et réglages sont conservés ; les fichiers remplacés sont sauvegardés (retour arrière possible). Aucun redémarrage du serveur : seule cette console redémarre à la fin.

          Ports ouverts
          
      
          
      
      
          Seuls ces ports sont joignables depuis le réseau. Les applications ajoutées dans Dockge qui publient un port doivent y figurer, sinon le garde de l'appliance bloque ce port.
